# 1.79 本地 AI 实测与正式交付

Gate: RELEASE READY（本轮约定的核心与 MuMu2 范围；真机未验证，没有人类试玩）

本轮结果：本地标准/困难 AI 已增强，困难对照显示优势；不是“无敌 AI”。保留 1.78 已满意的触屏和镜头，未修改战斗、移动、血量、盟友、道具、权威 RNG、dots 顺序、地图素材或协议。正式版 1.79 / versionCode48，协议28。线上发布回执以 github-publication.json、website-publication.json 为准；本地交付回执以 sync-verification.json 为准。

## 为什么旧版弱，改了什么

旧标准主要追最近敌方粒子；旧困难已有绕墙与简单兵力权重，却没有完整进退、目标记忆、主动抢道具及执行失败检查。Java指定道具主要按敌军总数选人。现在新增只读 C++ LocalTactics：32格局部观察桶、8格导航、危险代价、进攻/撤退/集结/支援/抢道具比较、目标迟滞和无进展重评估。困难分队每4次控制更新轮换规划，标准每8次；休闲保留慢追。线程仍是原游戏worker，不放到UI/GL线程。

死亡/朋友只选看见且未被对应道具保护的敌人；传送试算整队可落地空间，隐藏占位交由普通合法指令判定；重置优先用于明显兵力劣势；考虑现有20秒增益、配对反制、实体道具阻挡和地形变化。不是所有战术都在每局触发，也不是完整多步博弈搜索。

新控制器不消耗模拟随机数，旧本地 RNG 调用节奏保留。JNI 输出仍是现有5触点与合法道具 nonce；单机/房主复用，客户端不另算本地策略。模型队伍排除在mask外，无指令仍停住。暂停/倒计时/后台停止沿用生命周期；重置epoch与新局清缓存，障碍revision更新图，阵营及道具每次重新观察。

核实了 behaviac、gdx-ai、MicroRTS，最终没有接入额外库。原因、固定提交和许可见 [RESEARCH](RESEARCH.md)。新实现采用通用的态势评分和网格寻路方法，源码为 GPL-3.0-or-later；不把框架安装当作能力提升。

调优失败全部保留：v2曾有明显性能回退；v5边缘目标不可执行；v6传送会探知隐藏占位，均修正并复测。早期固定步数 full-v2 的数字仅是分数领先，不能作为完整比赛胜率；本报告只采用最终v7。详见 [FAILURES](FAILURES.md)。
